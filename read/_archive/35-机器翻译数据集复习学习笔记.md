## 1. 这份 notebook 在复习哪条主线

机器翻译和语言模型不同。

语言模型通常只有一条序列：

```text
前面的词元 -> 下一个词元
```

机器翻译有两条序列：

```text
源语言句子 -> 目标语言句子
```

所以数据处理时必须同时维护：

- source
- target
- source vocab
- target vocab
- source valid length
- target valid length

这就是这份 notebook 的主线。

## 2. 读取数据：从原始文本开始

代码中：

```python
def read_data_nmt():
    data_dir = d2l.download_extract('fra-eng')
    with open(os.path.join(data_dir, 'fra.txt'), 'r', encoding='utf-8') as f:
        return f.read()
```

它读取的是英法翻译数据。

每一行通常是：

```text
英文句子\t法文句子
```

也就是说，一行里包含一对翻译样本。

这类数据叫平行语料。

## 3. 预处理：让文本更规整

代码里做了：

```python
text = text.replace('\u202f', ' ').replace('\xa0', ' ').lower()
```

这一步做了两个清理：

1. 替换特殊空格
2. 统一转成小写

后面又把标点和单词分开。

这样可以减少词表混乱。

比如：

```text
go!
```

会变得更接近：

```text
go !
```

标点就能成为单独词元。

## 4. 词元化：拆成 source 和 target

代码中：

```python
source.append(parts[0].split(' '))
target.append(parts[1].split(' '))
```

这里把每一行拆成两个列表。

比如：

```text
go .    va !
```

会变成：

```text
source = ["go", "."]
target = ["va", "!"]
```

注意 source 和 target 必须一一对应。

如果顺序乱了，模型就会学到错误的翻译关系。

## 5. 为什么要看长度分布

notebook 里画了源语言和目标语言的长度直方图。

这一步是在帮你决定：

```text
num_steps 应该设置多长
```

如果 `num_steps` 太小，很多句子会被截断。

如果 `num_steps` 太大，大量位置会是 `<pad>`，计算浪费。

所以长度分布不是装饰图，它是为后面的超参数选择服务的。

## 6. 词表：源语言和目标语言分开建

代码中：

```python
src_vocab = d2l.Vocab(source, min_freq=2,
                      reserved_tokens=['<pad>', '<bos>', '<eos>'])
```

源语言和目标语言要分别建词表。

原因很简单：

```text
英语和法语不是同一套词
```

源语言词表负责把输入句子变成索引。

目标语言词表负责把输出句子变成索引，也负责把模型预测的索引还原成目标语言词。

## 7. 特殊词元再次确认

这章里三个特殊词元很重要。

### `<pad>`

用于填充短句。

### `<bos>`

表示目标序列开始，后面解码器会用到。

### `<eos>`

表示句子结束，模型生成时看到它就可以停。

你可以先把它们理解成序列任务中的控制符。

## 8. 截断和填充：让 batch 形状一致

代码中：

```python
def truncate_pad(line, num_steps, padding_token):
    if len(line) > num_steps:
        return line[:num_steps]
    return line + [padding_token] * (num_steps - len(line))
```

这一步解决的是：

```text
每个句子长度不同，但小批量张量需要统一形状
```

所以太长就截断。

太短就补 `<pad>`。

最后每条序列长度都等于 `num_steps`。

## 9. 有效长度为什么重要

代码中：

```python
valid_len = (array != vocab['<pad>']).type(torch.int32).sum(1)
```

它统计每条序列里非 `<pad>` 的词元数量。

这很关键。

因为 `<pad>` 只是为了凑齐形状，不是真实句子内容。

后面注意力机制和损失计算都需要知道：

```text
哪些位置是真实词元，哪些位置只是 padding
```

## 10. 最终返回的数据长什么样

`load_data_nmt` 返回：

```python
data_iter, src_vocab, tgt_vocab
```

其中每个 batch 包含：

```text
X, X_valid_len, Y, Y_valid_len
```

含义是：

- `X`：源语言句子索引
- `X_valid_len`：源语言有效长度
- `Y`：目标语言句子索引
- `Y_valid_len`：目标语言有效长度

这就是后面编码器-解码器模型要吃的数据格式。
