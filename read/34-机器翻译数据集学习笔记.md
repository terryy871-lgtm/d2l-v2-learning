## 1. 先用人话理解机器翻译数据

语言模型通常只有一条文本序列。

它学的是：

```text
前面的词元 -> 下一个词元
```

机器翻译不一样。

它的数据是一对一对的句子：

```text
英语句子 -> 法语句子
```

比如：

```text
go . -> va !
```

所以机器翻译是典型的序列到序列任务。

输入是一段序列，输出也是一段序列。

## 2. 读取英法数据集

notebook 中定义了：

```python
d2l.DATA_HUB['fra-eng'] = (...)
```

然后：

```python
def read_data_nmt():
    data_dir = d2l.download_extract('fra-eng')
    with open(os.path.join(data_dir, 'fra.txt'), 'r', encoding='utf-8') as f:
        return f.read()
```

这个文件中每一行通常包含一对翻译句子。

源语言和目标语言之间用制表符 `\t` 分隔。

所以后面需要按行、按 `\t` 拆开。

## 3. 为什么要预处理文本

代码中：

```python
text = text.replace('\u202f', ' ').replace('\xa0', ' ').lower()
```

这里处理了特殊空格，并转成小写。

然后又在标点前插入空格：

```python
'hello!' -> 'hello !'
```

这样做的原因是：

```text
希望标点符号也能成为独立词元
```

否则 `hello!` 和 `hello` 会被当成不同词，词表会变得更混乱。

## 4. `tokenize_nmt` 做了什么

核心代码是：

```python
parts = line.split('\t')
if len(parts) == 2:
    source.append(parts[0].split(' '))
    target.append(parts[1].split(' '))
```

它把每一行拆成：

- 源语言词元序列
- 目标语言词元序列

最终得到：

```text
source = [[英语句子1词元], [英语句子2词元], ...]
target = [[法语句子1词元], [法语句子2词元], ...]
```

注意源语言和目标语言是成对出现的。

它们的顺序不能乱。

## 5. 为什么要看句子长度分布

notebook 中画了源语言和目标语言的长度直方图。

这样可以观察：

- 大多数句子有多长
- 源语言和目标语言长度是否接近
- `num_steps` 该设多大比较合适

如果 `num_steps` 太短，很多句子会被截断。

如果 `num_steps` 太长，大量位置都是 padding，计算浪费。

所以句子长度分布能帮助我们选择固定序列长度。

## 6. 为什么源语言和目标语言要分别建词表

代码中：

```python
src_vocab = d2l.Vocab(source, ...)
tgt_vocab = d2l.Vocab(target, ...)
```

英语和法语的词不同。

所以它们需要两个词表：

- 源语言词表
- 目标语言词表

源语言词表用于编码输入句子。

目标语言词表用于编码输出句子。

后面模型预测时，输出空间对应的是目标语言词表。

## 7. 三个特殊词元是什么

代码中保留了：

```python
reserved_tokens=['<pad>', '<bos>', '<eos>']
```

它们非常重要。

### `<pad>`

用于填充短句子，让同一个 batch 中所有序列长度一致。

### `<bos>`

beginning of sequence，表示目标序列开始。

训练解码器时常用它作为第一个输入。

### `<eos>`

end of sequence，表示句子结束。

模型生成翻译时，如果预测到 `<eos>`，就可以停止。

## 8. 为什么要截断和填充

神经网络小批量训练要求张量形状一致。

但句子长度不同。

所以代码定义了：

```python
def truncate_pad(line, num_steps, padding_token):
    if len(line) > num_steps:
        return line[:num_steps]
    return line + [padding_token] * (num_steps - len(line))
```

如果句子太长，就截断。

如果句子太短，就填充 `<pad>`。

这样每个句子都变成固定长度。

## 9. 为什么要加 `<eos>`

在 `build_array_nmt` 中：

```python
lines = [l + [vocab['<eos>']] for l in lines]
```

每个句子末尾都加了 `<eos>`。

这告诉模型：

```text
这个句子到这里结束了
```

没有 `<eos>`，模型生成时就不知道什么时候该停。

所以 `<eos>` 是序列生成任务中特别关键的标记。

## 10. `valid_len` 是什么

代码中：

```python
valid_len = (array != vocab['<pad>']).type(torch.int32).sum(1)
```

它统计每个序列中非 `<pad>` 的长度。

也就是：

```text
真实有效词元数量
```

为什么需要它？

因为 padding 只是为了凑齐形状，不应该参与注意力或损失计算。

后面学习编码器-解码器和注意力机制时，`valid_len` 会非常重要。

## 11. `load_data_nmt` 封装了什么

这个函数完成一整套数据准备：

1. 读取原始文本
2. 文本预处理
3. 拆分源语言和目标语言
4. 分别构建词表
5. 转换成定长数组
6. 计算有效长度
7. 构建数据迭代器

最终返回：

```python
data_iter, src_vocab, tgt_vocab
```

也就是训练数据、源语言词表、目标语言词表。

## 12. 最后一段输出怎么看

代码中：

```python
for X, X_valid_len, Y, Y_valid_len in train_iter:
    print('X:', X.type(torch.int32))
    print('X的有效长度:', X_valid_len)

```

这里：

- `X` 是源语言句子索引
- `X_valid_len` 是源语言有效长度
- `Y` 是目标语言句子索引
- `Y_valid_len` 是目标语言有效长度

这正是后面机器翻译模型需要的数据格式。

学完这一章，最重要的是记住：

1. 机器翻译数据是源句子和目标句子的配对数据

3. `<pad>` 用于填充，`<bos>` 用于开始，`<eos>` 用于结束
