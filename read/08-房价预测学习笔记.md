## 1. 先用人话理解这份 notebook 在做什么

前面你学的很多例子，比如线性回归、Softmax 回归、多层感知机，大多是：

- 输入比较规整
- 特征格式比较统一
- 训练流程比较标准

但房价预测不一样，它是一个典型的表格数据任务，特点是：

- 有数值特征
- 有类别特征
- 有缺失值
- 目标值 `SalePrice` 的数值范围很大

所以这份 notebook 的重点其实变成了：

1. 先把原始表格整理成模型能吃的数值矩阵
2. 再训练一个回归模型
3. 用更合理的指标评估结果
4. 用交叉验证挑超参数
5. 最后生成 Kaggle 提交文件

## 2. 这份数据集长什么样

代码里先读了两个文件：

- 训练集：`kaggle_house_pred_train.csv`
- 测试集：`kaggle_house_pred_test.csv`

打印结果是：

```text
(1460, 81)
(1459, 80)
```

这表示：

- 训练集有 `1460` 条样本、`81` 列
- 测试集有 `1459` 条样本、`80` 列

为什么训练集比测试集多一列？因为训练集多了标签列：

```text
SalePrice
```

这就是我们要预测的房价。

你后面又打印了一部分列：

```text
Id  MSSubClass MSZoning LotFrontage SaleType SaleCondition SalePrice
```

从这里就能看出几个很典型的表格任务特点：

- `Id` 是样本编号，不是有效特征
- `LotFrontage` 这种是数值特征
- `MSZoning`、`SaleType` 这种是类别特征
- `SalePrice` 是监督学习里的标签

## 3. 为什么先把训练集和测试集拼起来

你这行代码很关键：

```python
all_features = pd.concat((train_data.iloc[:, 1:-1], test_data.iloc[:, 1:]))
```

这行代码做了两件事：

1. 把训练集里的 `Id` 和 `SalePrice` 去掉，只保留特征
2. 把训练集特征和测试集特征上下拼接起来

### 3.1 为什么要去掉 `Id`

因为 `Id` 本质上只是编号。

如果把它当特征喂给模型，模型可能会学到一些没有意义的关联，比如：

```text
编号越大，房价越高
```

这种规律通常是假的，属于噪声。

### 3.2 为什么训练集和测试集要一起预处理

这一步是很多初学者最容易疑惑的地方。

原因是：

- 训练集和测试集里的类别取值必须保持一致
- 独热编码之后，两边的列数和列名必须一一对齐

比如训练集里有某个区域类型，测试集里也可能出现；如果分开做 `get_dummies`，就可能出现：

- 训练集生成了某几列
- 测试集生成了另一组列

这样最后模型输入维度就对不上了。

所以更稳妥的做法是：

```text
先拼接，再统一做预处理，最后再切回训练部分和测试部分
```

这也是这类表格任务里非常常见的处理方式。

## 4. 数据预处理到底做了什么

这部分是整份 notebook 最值得反复看的地方。

## 4.1 找出数值特征

```python
numeric_features = all_features.dtypes[all_features.dtypes != 'object'].index
```

这行的意思是：

- 把数据类型不是 `object` 的列找出来
- 这些列通常就是数值列

因为在 Pandas 里，很多字符串类别列会显示为 `object`。

## 4.2 对数值特征做标准化

```python
all_features[numeric_features] = all_features[numeric_features].apply(
    lambda x: (x - x.mean()) / (x.std()))
```

标准化的作用可以理解成：

```text
把不同量纲、不同取值范围的数值特征拉到相近尺度上
```

为什么这一步重要？

因为表格里的数值特征可能差异很大，比如：

- 有的特征是几十
- 有的特征是几千
- 有的特征是几十万

如果不做标准化，大数值特征可能会在训练中“声音特别大”，影响优化过程。

标准化之后，每个数值特征大致都变成：

- 均值接近 `0`
- 标准差接近 `1`

这样优化器更容易训练。

## 4.3 用 `0` 填补数值特征缺失值

```python
all_features[numeric_features] = all_features[numeric_features].fillna(0)
```

这一步乍一看有点奇怪，因为原始数据里的 `0` 可能并不代表平均值。

但注意，它是在标准化之后才填 `0`。

标准化之后：

```text
0 代表这个特征的平均水平附近
```

所以这里相当于在说：

```text
如果某个数值特征缺失，就先把它补成“普通水平”
```

这是一个简单但很常见的 baseline 做法。

## 4.4 对类别特征做独热编码

```python
all_features = pd.get_dummies(all_features, dummy_na=True).astype(float)
```

这一步是在把类别变量变成神经网络能处理的数值变量。

例如：

```text
MSZoning = RL / RM / FV
```

不能直接送进线性层，因为模型不会理解字符串。

独热编码之后会变成类似：

- `MSZoning_RL`
- `MSZoning_RM`
- `MSZoning_FV`

某个样本属于哪一类，对应列就是 `1`，其余是 `0`。

### `dummy_na=True` 是什么意思

这表示：

```text
把缺失值也当成一种单独的类别
```

这很重要，因为在表格数据里，“缺失”本身有时就带有信息。

比如：

- 某个字段缺失，可能意味着这个房子没有某种设施
- 或者这个记录本身就属于特殊情况

所以让模型显式知道“这里缺了”，往往比简单丢掉更稳。

## 4.5 预处理后维度为什么变大了

运行完之后得到：

```text
(2919, 330)
```

这表示：

- 拼接后的总样本数是 `1460 + 1459 = 2919`
- 预处理后的总特征数变成了 `330`

为什么从原来的 80 左右列膨胀到了 330 列？

因为类别特征经过独热编码后，会拆成很多个二值列。

这也是表格任务里的常见现象：

```text
原始列数不多，但编码后特征维度会明显增加
```

## 5. 为什么最后要转成张量

```python
train_features = torch.tensor(...)
test_features = torch.tensor(...)
train_labels = torch.tensor(...)
```

因为前面的预处理是在 Pandas / NumPy 里完成的，而后面的模型训练是 PyTorch。

所以这里是在做格式切换：

- 表格处理阶段：`DataFrame`
- 模型训练阶段：`Tensor`

这里还顺手做了一件重要的事：

```python
train_data.SalePrice.values.reshape(-1, 1)
```

这说明标签被整理成了列向量形状：

```text
(样本数, 1)
```

这样和网络输出的形状就能对应起来。

## 6. 模型结构其实并不复杂

你定义的网络是：

```python
nn.Sequential(
    nn.Linear(in_features, 64),
    nn.ReLU(),
    nn.Linear(64, 1)
)
```

这说明你没有上特别复杂的深层网络，而是用了一个很基础的两层感知机：

- 输入层到隐藏层：`in_features -> 64`
- 激活函数：`ReLU`
- 隐藏层到输出层：`64 -> 1`

这个设计很能说明问题：

```text
这份 notebook 的重点不是炫复杂模型，而是先把表格数据处理对
```

在很多真实任务里，数据预处理的重要性并不比模型结构低。

## 7. 为什么训练时用 MSE，评估时却看 log rmse

训练损失定义的是：

```python
loss = nn.MSELoss()
```

这表示模型优化时直接最小化均方误差。

但真正评估时，用的是：

```python
log_rmse
```

定义是：

```python
clipped_preds = torch.clamp(net(features), 1, float('inf'))
rmse = torch.sqrt(loss(torch.log(clipped_preds), torch.log(labels)))
```

## 7.1 为什么要先取对数

因为房价这种数据往往跨度很大。

例如：

- 10 万和 12 万差 2 万
- 100 万和 102 万也差 2 万

从绝对误差看它们一样，但从相对误差看完全不同。

取对数之后，模型会更关注：

```text
预测值和真实值之间的相对偏差
```

这比直接看绝对差更符合房价任务的直觉。

## 7.2 为什么要先 `clamp`

```python
torch.clamp(net(features), 1, float('inf'))
```

这是为了防止预测值小于等于 `0`。

因为后面要做：

```python
torch.log(pred)
```

而对数函数要求输入是正数。

所以这里实际上是在做一个安全保护：

```text
先把预测值下界截到 1，避免 log 出现非法值
```

## 8. 训练函数里最值得看什么

训练函数本身很标准：

- 构造小批量数据
- 前向传播
- 计算损失
- 反向传播
- 优化器更新参数

这里最值得看的点有两个。

## 8.1 优化器用了 Adam

```python
optimizer = torch.optim.Adam(net.parameters(), lr=learning_rate,
                             weight_decay=weight_decay)
```

相比最基础的 SGD，Adam 通常在这类任务里更省心一些：

- 收敛更快
- 对学习率没那么敏感
- 对不同参数尺度的适应性更强

## 8.2 这里也用了权重衰减

你前面已经学过权重衰减，这里再次出现：

```python
weight_decay=weight_decay
```

它的作用还是那个核心思想：

```text
不要让模型参数变得过大，从而减轻过拟合
```

表格数据样本量有限、特征又不算少时，正则化通常是很自然的选择。

## 9. `K` 折交叉验证到底是在做什么

这部分是这份 notebook 另一个核心知识点。

很多人训练完一个模型，只看一次训练集表现，或者随便切一份验证集就结束了。但这样容易偶然性太强。

`K` 折交叉验证的思路是：

1. 把训练集分成 `K` 份
2. 每次拿其中 1 份做验证集
3. 剩下 `K-1` 份做训练集
4. 重复 `K` 次
5. 最后把 `K` 次验证结果取平均

这样做的好处是：

- 每个样本都做过验证集
- 结果比单次切分更稳
- 更适合在数据量不大的时候评估模型

## 9.1 `get_k_fold_data` 在做什么

这个函数的作用就是：

```text
第 i 折拿出来当验证集，其余折拼起来当训练集
```

这就是交叉验证最核心的“拆分数据”逻辑。

## 9.2 `k_fold` 在做什么

这个函数做的是：

- 对每一折都重新初始化一个新网络
- 单独训练
- 记录这一折的训练误差和验证误差
- 最后把所有折的结果平均

这里“每一折都重新初始化网络”很关键。

如果不重新初始化，而是沿用上一折训练后的参数，就会导致不同折之间互相污染，验证结果就不可信了。

## 10. 怎么理解你这次跑出来的结果

你当前输出是：

```text
折1，训练log rmse0.137049, 验证log rmse0.140949
折2，训练log rmse0.135938, 验证log rmse0.150223
折3，训练log rmse0.125602, 验证log rmse0.138181
折4，训练log rmse0.130935, 验证log rmse0.125181
折5，训练log rmse0.123021, 验证log rmse0.164687
5-折验证: 平均训练log rmse: 0.130509, 平均验证log rmse: 0.143844
```

从这些数字可以读出几件事。

### 10.1 训练误差整体低于验证误差

这是正常现象，说明模型在训练集上拟合得更好。

如果训练误差远低于验证误差，通常说明存在一定过拟合倾向。

你这里虽然没有夸张到失控，但已经能看出：

```text
模型在训练集上的表现比在验证集上更乐观
```

### 10.2 不同折之间波动不小

例如第 4 折和第 5 折的验证误差差得比较明显。

这说明：

- 数据划分不同，会影响结果
- 训练集规模不算特别大
- 当前模型对数据切分有一定敏感性

这恰恰说明交叉验证是有必要的。

如果你只看某一折，可能会误判模型到底好不好。

## 11. 为什么最后还要用全部训练集再训练一次

交叉验证的作用主要是评估和调参，不是最终提交模型。

所以最后的 `train_and_pred` 做的是：

1. 用全部训练数据重新训练一个模型
2. 不再留验证集
3. 直接对测试集做预测
4. 生成提交文件

这样做的逻辑很合理：

```text
既然超参数已经通过交叉验证大致确认了，最终模型就应该尽量利用全部训练数据
```

## 12. `submission.csv` 是怎么生成的

最后这几行很关键：

```python
preds = net(test_features).detach().numpy()
test_data['SalePrice'] = pd.Series(preds.reshape(1, -1)[0])
submission = pd.concat([test_data['Id'], test_data['SalePrice']], axis=1)
submission.to_csv('submission.csv', index=False)
```

这里的流程是：

1. 用训练好的模型预测测试集房价
2. 把预测结果塞回 `test_data`
3. 只保留 Kaggle 要求的两列：
   `Id` 和 `SalePrice`
4. 导出为 `submission.csv`

Kaggle 提交文件本质上就是一个标准格式表：

- 第一列：样本 `Id`
- 第二列：预测房价 `SalePrice`

## 13. 这份 notebook 真正要学会的不是“房价预测”，而是这些套路

学完这一章，你最该带走的不是某个具体分数，而是下面这些可复用的方法。

### 13.1 表格数据预处理套路

遇到表格任务时，先想：

- 哪些列是编号，要删掉
- 哪些列是标签，要单独拿出来
- 哪些列是数值特征
- 哪些列是类别特征
- 有没有缺失值

### 13.2 统一预处理训练集和测试集

尤其是做独热编码时，要注意：

```text
训练集和测试集的特征空间必须完全对齐
```

### 13.3 评价指标要和任务匹配

这个例子提醒你：

```text
训练损失和最终评价指标不一定完全相同
```

房价预测关心相对误差，所以 `log rmse` 比直接看普通 `rmse` 更合理。

### 13.4 数据不多时，交叉验证很重要

如果数据量有限，单次切分的结果往往不稳定。

这时：

```text
K 折交叉验证是更可靠的评估方式
```

## 14. 这份代码里几个你现在就该记住的细节

### 14.1 `download` 默认路径是相对路径

你前面已经发现了这个问题。

如果写成：

```python
cache_dir='data'
```

就会下载到当前 notebook 所在目录下的 `data` 文件夹。

如果写成：

```python
cache_dir=os.path.join('..', 'data')
```

就会下载到上一层目录里的 `data` 文件夹。

所以相对路径到底落在哪，要始终结合“当前工作目录”一起看。

### 14.2 `train_data.iloc[:, 1:-1]` 很值得记

它的意思是：

- 去掉第 0 列 `Id`
- 去掉最后一列 `SalePrice`
- 中间全都作为特征

这是一种非常常见的表格切片写法。

### 14.3 `reshape(-1, 1)` 是把标签整理成列向量

这个写法以后会反复见到。

其中 `-1` 的意思是：

```text
这一维让系统自动推断
```

最终得到的就是：

```text
(样本数, 1)
```
