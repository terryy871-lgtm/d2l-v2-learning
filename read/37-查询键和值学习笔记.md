## 1. 为什么要学查询、键和值

在前面的 Seq2Seq 模型中，编码器把整个源句子压缩成一个最终隐藏状态，再交给解码器。

这种做法有一个问题：

```text
源句子越长，一个固定长度的隐藏状态越难保存所有细节
```

比如翻译一句较长的英文句子时，解码器生成每个法文词时关注的英文位置可能不同。

生成第一个词时，可能更关注主语。

生成动词时，可能更关注谓语。

生成宾语时，可能更关注名词短语。

所以更自然的做法是：

```text
每次生成输出时，都动态决定应该重点看输入序列的哪些位置
```

这就是注意力机制要解决的问题。

而注意力机制的基本语言就是：

- 查询：query
- 键：key
- 值：value

## 2. 用生活例子理解 query、key、value

可以把注意力机制想成在资料库里查东西。

假设你有很多资料卡片，每张卡片都有：

```text
key：这张卡片的索引或标签
value：这张卡片真正保存的内容
```

当你提出一个问题时，这个问题就是：

```text
query
```

系统会拿 query 去和每个 key 比较，判断哪些卡片更相关。

相关性越高，对应 value 的权重越大。

最后输出不是只取一张卡片，而是对所有 value 做加权平均。

可以写成：

```text
输出 = value1 * 权重1 + value2 * 权重2 + ... + valueN * 权重N
```

这就是注意力汇聚。

## 3. query、key、value 分别是什么

在注意力机制中：

### query

query 表示“我现在想找什么”。

在翻译任务里，解码器当前时间步的隐藏状态可以作为 query。

它表达的是：

```text
我现在准备生成目标句子的下一个词，所以我想知道源句子中哪些部分最有用
```

### key

key 表示“每个候选信息的位置特征”。

在翻译任务里，编码器每个时间步的输出可以作为 key。

它表达的是：

```text
源句子每个词位置分别携带了什么线索
```

### value

value 表示“真正要被取出来的信息内容”。

很多模型中，key 和 value 可以来自同一批编码器输出。

区别在于：

```text
key 用来算相关性，value 用来被加权求和
```

这两个角色逻辑上不同，即使它们有时来自同一个张量。

## 4. 注意力权重是什么

query 和每个 key 比较后，会得到一组分数。

这些分数经过 softmax 后变成注意力权重。

注意力权重通常满足：

```text
每个权重 >= 0
所有权重之和 = 1
```

如果某个 key 和 query 很匹配，它的权重就大。

如果不匹配，权重就小。

例如有 4 个 key：

```text
权重 = [0.05, 0.10, 0.80, 0.05]
```

说明当前 query 主要关注第 3 个 value。

注意力机制的输出就是：

```text
0.05 * value1 + 0.10 * value2 + 0.80 * value3 + 0.05 * value4
```

这比只看一个固定隐藏状态灵活得多。

## 5. 注意力和普通加权平均的关系

注意力本质上可以看成一种加权平均。

区别是权重不是手动指定的，而是模型根据 query 和 key 自动计算出来的。

普通平均是：

```text
每个 value 权重一样
```

注意力是：

```text
不同 value 根据相关性分配不同权重
```

所以注意力机制并不神秘。

它真正厉害的地方在于：

```text
权重是动态的，会随着 query 的变化而变化
```

同一批 key-value，在不同 query 下会产生不同输出。

## 8. 为什么用热力图看注意力

注意力权重是一个矩阵。

如果直接看数字，会很难快速理解模式。

例如：

```text
[[1, 0, 0],
 [0, 1, 0],
 [0, 0, 1]]
```

数字看起来还好。

但当矩阵变成几十乘几十时，直接看数字就很痛苦。

热力图可以让我们一眼看出：

- 每个 query 主要关注哪些 key
- 注意力是否集中
- 注意力是否分散
- 是否存在对角线模式
- 不同 head 是否学到不同关注方式

所以 `show_heatmaps` 不是模型本体，但它是理解注意力机制的重要工具。

## 9. 单位矩阵注意力表示什么

notebook 中构造：

```python
attention_weights = torch.eye(10).reshape((1, 1, 10, 10))
```

`torch.eye(10)` 是 10 阶单位矩阵。

它长这样：

```text
第 1 行第 1 列为 1
第 2 行第 2 列为 1
...
第 10 行第 10 列为 1
其他位置为 0
```

把它解释成注意力权重，就是：

```text
第 i 个 query 只关注第 i 个 key
```

这会在热力图上形成一条明显的对角线。

## 10. 为什么 reshape 成四维

代码中：

```python
attention_weights = torch.eye(10).reshape((1, 1, 10, 10))
```

原本单位矩阵形状是：

```text
(10, 10)
```

为了适配 `show_heatmaps`，需要变成：

```text
(1, 1, 10, 10)
```

含义是：

- 第一个 `1`：只有 1 行图
- 第二个 `1`：只有 1 列图
- `10`：有 10 个 query
- `10`：有 10 个 key

这只是为了绘图接口统一。

真正的注意力矩阵仍然是最后的：

```text
10 x 10
```

## 12. 容易混淆的点

### key 和 value 为什么分开

key 是用来匹配 query 的。

value 是最终被汇总的信息。

它们有时来自同一个输入，但语义角色不同。

### 注意力权重不是参数

注意力权重通常不是直接训练出来的一组固定参数。

它是根据当前 query 和 key 动态计算出来的结果。

模型会训练用于计算 query、key、value 或评分函数的参数。

### 注意力不是只选一个位置

注意力可以很集中，也可以很分散。

它通常是对所有 value 做加权和，而不是硬性选择其中一个。
