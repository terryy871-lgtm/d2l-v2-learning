# 09 层和块学习笔记

这份笔记是结合你的文件 [Layers_and_Modules.ipynb](</D:/Learn/d2l-test/Builders_Guide/Layers_and_Modules.ipynb>) 写的，目标不是只记住几段 PyTorch 语法，而是帮你真正理解：

- 什么是层，什么是块
- 为什么 PyTorch 里很多模型都继承自 `nn.Module`
- `nn.Sequential` 到底帮我们做了什么
- 为什么我们可以自己定义块
- 为什么 `forward` 里不只是“堆层”，还可以写普通 Python 逻辑
- 块和块之间又是怎么嵌套起来组成更复杂模型的

如果用一句话概括这一章：

```text
层是完成某种变换的基本单元，块是把一层或多层以及前向传播逻辑封装起来的更高一级模块
```

## 1. 先用人话理解“层”和“块”

在前面学线性回归、多层感知机时，你已经接触过：

- `nn.Linear`
- `nn.ReLU`
- `nn.Sequential`

但那时候更像是在“会用”，这一章开始强调的是：

```text
模型本身是怎么组织起来的
```

可以先这样理解：

### 层

层通常是一次比较明确的变换，比如：

- 线性变换
- 激活函数
- 卷积
- 池化

例如：

```python
nn.Linear(20, 256)
```

它就是一个层。

### 块

块可以看成是更大的组件，它可以包含：

- 一层
- 多层
- 参数
- 前向传播逻辑

比如一个 MLP 可以是一个块，一个残差块也可以是一个块。

所以：

```text
层偏向“局部操作”，块偏向“可复用结构”
```

而在 PyTorch 里，这些块通常都继承自：

```python
nn.Module
```

## 2. 第一段代码在做什么

你一开始写的是：

```python
net = nn.Sequential(
    nn.Linear(20, 256),
    nn.ReLU(),
    nn.Linear(256, 10)
)

X = torch.rand(2, 20)
net(X)
```

这段代码本质上就是在搭一个最简单的前馈网络：

```text
输入 20 维
-> 线性层映射到 256 维
-> ReLU 激活
-> 再映射到 10 维输出
```

这里最关键的不是输出数值本身，而是要理解：

```text
nn.Sequential 会把你传进去的层按顺序串起来
```

也就是说，它自动帮你完成了类似下面的前向传播逻辑：

```python
X = layer1(X)
X = layer2(X)
X = layer3(X)
```

所以 `nn.Sequential` 适合什么场景？

- 网络就是简单地从前往后顺序流动
- 不需要分支
- 不需要跳连
- 不需要特殊控制逻辑

这种时候它非常省事。

## 3. 为什么要自定义块

第二部分你定义了：

```python
class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.hidden = nn.Linear(20, 256)
        self.out = nn.Linear(256, 10)

    def forward(self, X):
        return self.out(F.relu(self.hidden(X)))
```

这段代码是这一章最核心的入门点，因为它第一次明确告诉你：

```text
PyTorch 的模型本质上就是一个继承自 nn.Module 的类
```

## 3.1 `__init__` 在做什么

`__init__` 里主要是定义这个块里有哪些子层、参数和组件。

这里你定义了：

- `self.hidden`
- `self.out`

也就是说，这个块内部包含两层线性层。

这一阶段你可以把 `__init__` 理解成：

```text
先把模型里要用到的零件准备好
```

## 3.2 `forward` 在做什么

`forward` 负责定义：

```text
输入进来之后，数据到底怎么流动
```

这里的流程是：

1. 先过隐藏层 `self.hidden(X)`
2. 再过 `ReLU`
3. 最后过输出层 `self.out(...)`

这就是一个标准的 MLP 前向传播。

## 3.3 为什么一定要写 `super().__init__()`

这一步是在初始化父类 `nn.Module`。

如果不写它，PyTorch 就不能正确管理这个类里的子模块和参数。

你可以把它理解成：

```text
先把 Module 这套“模块管理系统”启动起来，后面你定义的层才能被正确注册
```

## 4. 为什么说 `nn.Module` 很重要

这一章表面在讲“层和块”，其实底层都绕不开 `nn.Module`。

只要一个类继承了 `nn.Module`，它通常就自动获得很多能力，比如：

- 管理子模块
- 管理参数
- 支持前向调用
- 支持 `.parameters()`
- 支持迁移到 GPU
- 支持保存和加载参数

所以以后你看到：

```python
class SomeNet(nn.Module):
```

本质上都可以理解为：

```text
我现在要定义一个可以被 PyTorch 当成模型使用的块
```

## 5. 自己实现 `Sequential` 到底是在学什么

你写的这一段非常值得看：

```python
class MySequential(nn.Module):
    def __init__(self, *args):
        super().__init__()
        for idx, module in enumerate(args):
            self._modules[str(idx)] = module

    def forward(self, X):
        for block in self._modules.values():
            X = block(X)
        return X
```

这段代码的意义不在于“以后都自己手写 Sequential”，而在于帮你看懂：

```text
Sequential 的工作原理其实并不神秘，就是把一组模块存起来，然后在 forward 里按顺序依次调用
```

## 5.1 `*args` 是什么意思

`*args` 表示可以接收任意多个位置参数。

所以你后面才能这样写：

```python
MySequential(nn.Linear(20, 256), nn.ReLU(), nn.Linear(256, 10))
```

这些模块会被统一收到 `args` 里。

## 5.2 `enumerate(args)` 在做什么

这里是边遍历边编号。

例如传进来三个模块时，`enumerate(args)` 大致会得到：

- `0, 第一个模块`
- `1, 第二个模块`
- `2, 第三个模块`

然后你把它们存到：

```python
self._modules[str(idx)]
```

里。

## 5.3 `self._modules` 是什么

这是 `nn.Module` 内部用来保存子模块的一个有序字典。

你把模块放进去后，PyTorch 就知道：

- 这个类里有哪些子模块
- 这些子模块的参数是什么

也就是说，`MySequential` 能工作，很大程度上就是因为它利用了 `nn.Module` 提供的模块注册机制。

## 5.4 `forward` 里发生了什么

```python
for block in self._modules.values():
    X = block(X)
return X
```

这段代码本质上就是：

```text
把输入按顺序交给每一个子块处理
```

所以你可以把 `MySequential` 理解成 `nn.Sequential` 的简化版原理演示。

## 6. `forward` 里不只是“堆层”

这一章最容易让人眼前一亮的地方，是这个块：

```python
class FixedHiddenMLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.rand_weight = torch.rand((20, 20), requires_grad=False)
        self.linear = nn.Linear(20, 20)

    def forward(self, X):
        X = self.linear(X)
        X = F.relu(torch.mm(X, self.rand_weight) + 1)
        X = self.linear(X)
        while X.abs().sum() > 1:
            X /= 2
        return X.sum()
```

这一段真正想说明的是：

```text
forward 里不仅能写层调用，还能写普通张量运算、参数共享、循环、条件判断等 Python 逻辑
```

这就是 PyTorch 动态计算图风格一个很重要的特点。

## 6.1 `rand_weight` 为什么不是可训练参数

```python
self.rand_weight = torch.rand((20, 20), requires_grad=False)
```

这里生成了一个固定随机权重，并明确设置：

```python
requires_grad=False
```

这表示它不会在反向传播中更新。

也就是说，这个权重只是前向传播里要用到的一个常量张量，不是模型要学习的参数。

## 6.2 为什么同一个 `linear` 被用了两次

你在 `forward` 里写了两次：

```python
X = self.linear(X)
...
X = self.linear(X)
```

这说明：

```text
同一个层对象可以在前向传播里重复使用
```

而且重复使用意味着：

```text
两次用的是同一组参数，不是两套不同参数
```

这其实就是一种参数共享。

## 6.3 `torch.mm` 在做什么

```python
torch.mm(X, self.rand_weight)
```

它是在做矩阵乘法。

这里表示：

- 先经过可训练线性层
- 再和一个固定随机矩阵相乘
- 再经过 `ReLU`

这一步说明块内部并不一定全靠 `nn.Linear` 这种现成层，也可以手动写张量变换。

## 6.4 `while` 循环说明了什么

```python
while X.abs().sum() > 1:
    X /= 2
```

这一段非常关键，因为它说明：

```text
前向传播里可以有控制流
```

也就是说，模型并不一定非要是“固定层数、固定步骤”的死板结构。

它可以根据当前张量的值，动态决定是否继续执行某段逻辑。

这也是为什么说 PyTorch 的 `forward` 很灵活。

## 6.5 为什么最后返回的是标量

```python
return X.sum()
```

这一步把整个输出张量压成了一个标量。

所以这个块最终输出的不再是：

```text
(batch_size, feature_dim)
```

而是一个单独的数值张量。

这也再次说明：

```text
块的输出形式并不一定非要和普通层一样，它完全取决于你在 forward 里怎么写
```

## 7. 嵌套块是在说明什么

最后一部分你定义了：

```python
class NestMLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(20, 64),
            nn.ReLU(),
            nn.Linear(64, 32),
            nn.ReLU()
        )
        self.linear = nn.Linear(32, 16)

    def forward(self, X):
        return self.linear(self.net(X))
```

然后又写了：

```python
chimera = nn.Sequential(
    NestMLP(),
    nn.Linear(16, 20),
    FixedHiddenMLP()
)
```

这部分是整章最后的总收束，它在告诉你：

```text
块可以包含层，块也可以包含别的块，最终模型就是这样一层层嵌套出来的
```

## 7.1 `NestMLP` 自己就是一个块

`NestMLP` 里面包含：

- 一个 `Sequential`
- 一个单独的线性层

所以它本身已经不是简单单层结构，而是一个更复杂的复合块。

## 7.2 `chimera` 又把多个块拼起来

这里的 `chimera` 更进一步：

1. 先经过 `NestMLP`
2. 再过一个 `Linear(16, 20)`
3. 最后交给 `FixedHiddenMLP`

这就说明：

```text
对于 PyTorch 来说，只要一个对象是 nn.Module，它就既可以单独使用，也可以继续作为别人的子模块
```

这和搭积木非常像。

## 8. 这章真正要学会的主线

如果把整份 notebook 按学习主线压缩，可以概括成下面四步。

### 8.1 先学会使用现成块

比如：

```python
nn.Sequential(nn.Linear(...), nn.ReLU(), nn.Linear(...))
```

这是最快的搭模型方式。

### 8.2 再学会定义自己的块

也就是：

```python
class SomeBlock(nn.Module):
```

然后在里面写：

- `__init__`
- `forward`

### 8.3 再理解块内部逻辑可以很灵活

块内部不一定只是机械地堆层，还可以有：

- 张量运算
- 参数共享
- 控制流
- 固定常量

### 8.4 最后理解块可以嵌套

复杂模型本质上就是：

```text
大块里面套中块，中块里面套小块，小块里面再放具体层
```

这就是深度学习框架组织模型的核心方式。

## 10. 这份 notebook 里你现在最该记住的几点

### 10.1 `nn.Module` 是 PyTorch 模型系统的核心基类

以后看到自定义网络，先想到：

```text
本质就是在定义一个 Module
```

### 10.2 `__init__` 负责声明组件，`forward` 负责定义数据流

这个分工一定要牢牢记住。

可以把它简化成：

- `__init__`：准备零件
- `forward`：规定输入怎么走

### 10.3 `Sequential` 只是最简单的块

它很方便，但只适合线性顺序结构。

一旦有复杂逻辑，自定义 `Module` 才是更通用的方式。

### 10.4 `forward` 可以写普通 Python 逻辑

这一点非常重要，因为它决定了：

```text
PyTorch 的模型定义是灵活的、动态的
```

### 10.5 块是可以嵌套的

这一点决定了我们可以不断把复杂模型拆成小模块，再把小模块重新组合。

## 11. 最后用几句话总结

这一章表面上在讲“层和块”，其实本质是在帮你建立一个非常重要的框架思维：

```text
不要把模型只看成一堆零散层，而要把它看成由多个可复用模块拼装起来的结构系统
```

学完这一章之后，你再看后面的模型代码时，就不应该只盯着某一层的输入输出，而要开始习惯问自己：

- 这个类是不是一个 `nn.Module`
- 它里面注册了哪些子模块
- `forward` 的数据流是怎么走的
- 这个块能不能被复用到更大的模型里

当你开始这样看代码时，就说明你已经在从“会跑 notebook”往“真正看懂深度学习框架里的模型实现”进步了。
