如果用一句话概括这一章：

```text

```

## 1. 先用人话理解“自定义层”在解决什么

前面你已经学过：

- 用现成层搭模型
- 自定义块
- 管理参数

但这些都还是在 PyTorch 已经提供好基础层的前提下进行的。

这一节更进一步，开始回答：

```text
如果框架里没有我想要的层，我能不能自己写？
```

答案是：

```text
可以，而且方法和自定义块非常像
```

因为在 PyTorch 里，层和块本质上都可以看成：

```python
nn.Module
```

也就是说：

```text
“层”并不是某种神秘特殊对象，它也只是一个带前向计算逻辑的模块
```

## 2. 第一部分为什么先写“不带参数的层”

你先定义了：

```python
class CenteredLayer(nn.Module):
    def __init__(self):
        super().__init__()

    def forward(self, X):
        return X - X.mean()
```

这一段很短，但很重要，因为它先让你看到：

```text
自定义层不一定非要有可学习参数
```

## 2.1 `CenteredLayer` 到底在做什么

它的前向传播只有一行：

```python
return X - X.mean()
```

意思就是：

- 先计算输入 `X` 的平均值
- 再让输入里的每个元素都减去这个平均值

所以它完成的是一种“中心化”操作。

例如输入：

```python
[1, 2, 3, 4, 5]
```

平均值是：

```text
3
```

减完之后就变成：

```text
[-2, -1, 0, 1, 2]
```

这也正好对应了你的输出结果。

## 2.2 为什么说它是“层”

虽然它没有：

- `weight`
- `bias`

但它依然做了一次明确的输入变换。

所以从功能角度说，它已经是一个层了。

这一步是在帮你打破一个很常见的误解：

```text
层不一定等于“带权重的线性层”，只要它对输入进行了封装好的变换，它就可以是层
```

## 2.3 为什么这里也要继承 `nn.Module`

即使这个层没有参数，它还是继承了：

```python
nn.Module
```

因为这样它才能：

- 统一使用 PyTorch 的模块接口
- 被放进 `Sequential`
- 和别的层自然组合

这说明：

```text
nn.Module 不只是给“有参数层”用的，而是给所有模块化层结构用的
```

## 3. 为什么它能直接放进 `Sequential`

你接着写了：

```python
net = nn.Sequential(nn.Linear(8, 128), CenteredLayer())
```

然后：

```python
Y = net(torch.rand(4, 8))
Y.mean()
```

输出结果非常接近：

```text
0
```

这正好说明：

```text
前面的线性层先产生输出，后面的 CenteredLayer 再把这份输出整体中心化
```

也就是说，你自定义的层已经和官方层没有使用方式上的区别了。

只要它是一个合法的 `Module`，就可以像积木一样接进网络里。

## 4. 第二部分为什么开始写“带参数的层”

前半部分说明：

```text
我们可以自己定义一种没有参数的变换
```

后半部分进一步说明：

```text
我们也可以自己定义有可学习参数的层
```

这就是你写的：

```python
class MyLinear(nn.Module):
    def __init__(self, in_units, units):
        super().__init__()
        self.weight = nn.Parameter(torch.randn(in_units, units))
        self.bias = nn.Parameter(torch.randn(units,))

    def forward(self, X):
        linear = torch.matmul(X, self.weight.data) + self.bias.data
        return F.relu(linear)
```

这段代码是这一节真正的核心。

## 4.1 这段代码本质上是在手写什么

你可以把它理解成：

```text
我自己手动实现了一个“线性变换 + ReLU”的层
```

它做的事情和前面熟悉的：

```python
nn.Linear(...) + nn.ReLU()
```

在思想上是一样的，只是这里不再调用现成层，而是自己把参数和计算过程写出来。

## 5. `nn.Parameter` 为什么这么关键

这一段最关键的两行是：

```python
self.weight = nn.Parameter(torch.randn(in_units, units))
self.bias = nn.Parameter(torch.randn(units,))
```

## 5.1 为什么不能只写普通张量

如果你只是写：

```python
self.weight = torch.randn(...)
```

那它只是普通张量。

虽然它也能参与计算，但 PyTorch 不会自动把它登记成模型参数。

这就意味着：

- `model.parameters()` 里找不到它
- 优化器不会更新它
- 保存模型时它也不会被正常纳入参数管理

所以这里必须用：

```python
nn.Parameter
```

## 5.2 `Parameter` 的本质直觉

你可以继续沿用前一节的理解：

```text
Parameter = 一个会被 Module 自动识别和跟踪的可训练张量
```

所以自定义层要想“真的可训练”，关键不是会不会写 `matmul`，而是：

```text
你有没有把需要学习的张量声明成 Parameter
```

## 6. `weight` 和 `bias` 的形状为什么这样写

你这里定义的是：

```python
self.weight = nn.Parameter(torch.randn(in_units, units))
self.bias = nn.Parameter(torch.randn(units,))
```

如果输入 `X` 的形状是：

```text
(batch_size, in_units)
```

那么：

```python
torch.matmul(X, self.weight)
```

之后会得到：

```text
(batch_size, units)
```

再加上形状为：

```text
(units,)
```

的偏置，广播后依然能对上。

这说明你现在已经不是只会“调包”，而是在真正理解：

```text
参数形状必须和矩阵运算逻辑对齐
```

## 7. `forward` 到底在做什么

你写的是：

```python
linear = torch.matmul(X, self.weight.data) + self.bias.data
return F.relu(linear)
```

可以拆成两步。

### 第一步：线性变换

```python
torch.matmul(X, self.weight.data) + self.bias.data
```

这一步本质就是：

```text
XW + b
```

这就是最标准的线性层计算。

### 第二步：非线性激活

```python
F.relu(linear)
```

这表示再接一个 `ReLU`。

所以这个层不是纯粹的“Linear”，而更像是：

```text
Linear + ReLU 的组合层
```

## 8. 为什么这里能输出很多 0

你测试后看到输出类似：

```text
tensor([[0.7439, 0.0000, 1.1730],
        [0.5192, 0.0859, 0.6098]])
```

有些位置是 `0`，原因很直接：

```text
ReLU 会把负数截断成 0
```

这说明你的自定义层不仅真的跑通了，而且行为也和你熟悉的 `ReLU` 网络一致。

## 9. 为什么说 `MyLinear` 已经是“真正可用的层”

你后面写了：

```python
net = nn.Sequential(MyLinear(64, 8), MyLinear(8, 1))
net(torch.rand(2, 64))
```

这一步的意义非常大，因为它证明了：

```text
你自定义的层可以像官方层一样继续组合成更大的网络
```

换句话说：

- `MyLinear(64, 8)` 是一个合法层
- `MyLinear(8, 1)` 也是一个合法层
- 它们可以被 `Sequential` 串起来

这就说明你已经不只是“写了个类”，而是真的写出了：

```text
框架可以识别、可以组合、可以前向传播的层
```

## 10. 这一节最重要的思想转变是什么

这节最重要的不是某个 API，而是一个认知升级：

```text
以前你觉得层是框架提供给你的；现在你开始知道，层本身也只是一个由参数和计算逻辑组成的模块
```

也就是说，官方层和你自定义的层，在本质上差别没有那么大：

- 都继承自 `nn.Module`
- 都可以有参数
- 都定义 `forward`
- 都可以被组合进更大模型

## 11. 不带参数层和带参数层的区别要怎么记

这一节其实正好给你一个很清晰的二分法。

### 11.1 不带参数层

例如 `CenteredLayer`。

特点是：

- 没有需要学习的参数
- 只做固定规则的变换
- 更像一种封装好的数据处理操作

### 11.2 带参数层

例如 `MyLinear`。

特点是：

- 有可训练参数
- 参数会随着训练更新
- 是模型表达能力的重要来源

所以你可以这样记：

```text
有些层负责“按固定规则处理”，有些层负责“带着参数去学习”
```

## 12. 这节和前面几节是怎么连起来的

这节和前面的“层和块”“参数管理”其实是自然衔接的。

### 和“层和块”的联系

前一节你学到：

```text
层和块本质上都是 Module
```

这一节就把这个结论往前推进了一步：

```text
既然层本质上也是 Module，那我们当然也可以自己定义层
```

### 和“参数管理”的联系

前一节你学到：

```text
参数需要被 Module 正确登记和管理
```

这一节里 `nn.Parameter` 的出现，正是在把那个知识点真正用起来。

因为自定义层如果不正确声明参数，就不能被正常训练。

## 13. 这一节里你现在最该记住的几点

### 13.1 自定义层的入口仍然是 `nn.Module`

以后只要你想自己写层，第一反应就应该是：

```python
class MyLayer(nn.Module):
```

### 13.2 没有参数的层也完全合理

不是所有层都必须带 `weight` 和 `bias`。

只要它完成了清晰的输入变换，它就可以是层。

### 13.3 需要训练的张量必须声明成 `nn.Parameter`

这是这节最关键的技术点之一。

### 13.4 `forward` 里写的就是层的数学计算过程

你怎么写 `forward`，这个层就怎么工作。

### 13.5 自定义层也能继续被组合

只要写得符合 `Module` 规范，它就能继续放进：

- `Sequential`
- 更大的自定义块
- 更复杂的模型结构

## 14. 关于这份代码里一个值得你留意的小点

你这里在 `forward` 中写的是：

```python
self.weight.data
self.bias.data
```

从教学演示角度，这样写能更直接地看到“我在用参数的数值做计算”。

但如果从更规范的 PyTorch 习惯来说，通常更自然的写法会是直接写：

```python
self.weight
self.bias
```

因为 `Parameter` 本身就可以参与计算图。

不过就这份 notebook 的学习目的而言，它最主要是在帮你理解：

```text
这些参数确实是我们亲手定义、亲手拿来做运算的
```

这个目标已经达到了。
