```text
GRU 的核心思想是：用门控机制决定隐藏状态应该记住多少过去、接收多少新信息
```

## 1. 为什么需要 GRU

普通 RNN 的隐藏状态不断更新：

```text
H_t = tanh(X_t W_xh + H_{t-1} W_hh + b_h)
```

这个结构简单，但问题是：

```text
它每一步都会强制把旧状态和新输入混合起来
```

当序列很长时，模型可能很难保留很久以前的重要信息。

也可能因为反复矩阵乘法出现梯度消失或梯度爆炸。

GRU 的设计目标就是：

```text
让模型自己学会什么时候记住旧信息，什么时候写入新信息
```

## 2. GRU 有哪些门

GRU 有两个主要门：

1. 更新门（update gate）
2. 重置门（reset gate）

它们都是由当前输入和上一隐藏状态计算出来的，取值通常在 0 到 1 之间。

可以把门理解成：

```text
一个可学习的开关或比例控制器
```

它不是手工规则，而是模型通过训练学出来的。

## 3. 更新门控制什么

更新门通常记作 `Z`。

它决定：

```text
当前隐藏状态有多少来自旧隐藏状态，有多少来自新候选状态
```

如果更新门接近 1，模型更倾向于保留旧状态。

如果更新门接近 0，模型更倾向于使用新信息。

所以更新门解决的是：

```text
记忆要保留多久
```

这对长期依赖非常重要。

## 4. 重置门控制什么

重置门通常记作 `R`。

它决定：

```text
计算候选隐藏状态时，要使用多少旧隐藏状态
```

如果重置门接近 0，旧状态会被大量忽略。

如果重置门接近 1，旧状态会更多参与候选状态计算。

所以重置门解决的是：

```text
生成新内容时，要不要参考过去
```

这让模型可以在需要时“重置”部分历史信息。

## 5. 从零实现中的参数有哪些

代码中有：

```python
self.W_xz, self.W_hz, self.b_z = three()
self.W_xr, self.W_hr, self.b_r = three()
self.W_xh, self.W_hh, self.b_h = three()
```

三组参数分别对应：

- 更新门 `Z`
- 重置门 `R`
- 候选隐藏状态 `H_tilde`

每一组都有：

- 输入到隐藏的权重
- 隐藏到隐藏的权重
- 偏置

这说明 GRU 比普通 RNN 参数更多，但控制能力也更强。

## 6. `forward` 中发生了什么

GRU 每个时间步大致做：

```python
Z = sigmoid(X @ W_xz + H @ W_hz + b_z)
R = sigmoid(X @ W_xr + H @ W_hr + b_r)
H_tilde = tanh(X @ W_xh + (R * H) @ W_hh + b_h)
H = Z * H + (1 - Z) * H_tilde
```

这里最关键的是最后一行：

```text
新隐藏状态 = 一部分旧状态 + 一部分候选新状态
```

这个比例由更新门 `Z` 控制。

这就是 GRU 能保留长期信息的核心。

## 7. 候选隐藏状态是什么

候选隐藏状态可以理解成：

```text
如果这一步要写入新信息，模型准备写入什么内容
```

但它不是直接成为最终隐藏状态。

最终隐藏状态还要由更新门决定：

```text
要写多少进去
```

所以 GRU 比普通 RNN 多了一层选择能力。

普通 RNN 是直接更新。

GRU 是先生成候选，再决定融合比例。

```text

```

### 简洁实现

```text
使用 PyTorch 官方 GRU，适合实际训练
```

以后真正做项目时，更常用 `nn.GRU`。

## 9. 为什么 GRU 常用于语言模型

语言有明显的上下文依赖。

有些信息只影响下一个字符，有些信息可能影响很远之后。

GRU 的门控机制允许模型学会：

- 哪些信息短期用完就忘
- 哪些信息需要保留更久
- 什么时候忽略旧上下文
- 什么时候更新隐藏状态

所以 GRU 比普通 RNN 更适合长序列。

1. GRU 是带门控机制的 RNN

3. 重置门决定生成候选状态时参考多少过去
4. 候选隐藏状态表示准备写入的新信息
5. `nn.GRU` 是手写 GRU 的框架封装版本

```text

```
